# Accessibility

**Read at:** phase 1 (constraints), phase 4 (verification).

Target: WCAG 2.2 Level AA. In several jurisdictions this is now enforceable law for
consumer-facing and public-sector digital products, not a guideline.

Everything below is a number or a binary. That is deliberate - "accessible" is not checkable, but
"the focus ring is 2px at 3.4:1" is.

---

## Contrast

| Content | Ratio |
| --- | --- |
| Body text, and any text under 18.66px, or under 24px bold | **4.5:1** |
| Large text: 24px+, or 18.66px+ bold | **3:1** |
| Icons and graphics needed to understand content | **3:1** |
| Boundaries needed to identify a control (input borders, unfilled buttons) | **3:1** |
| Focus indicator vs the adjacent background | **3:1** |
| Decorative graphics, disabled controls, logotypes | exempt |

Three failures that happen constantly:

- **Muted text via opacity.** `opacity: 0.5` on passing body text lands near 2.5:1. Muted text needs
  its own verified token.
- **Placeholder text.** Almost always fails, and it is often carrying the field's label. See below.
- **Text on the brand fill.** A mid-lightness brand frequently fails against both white and
  near-black. If it fails both, change the brand lightness - do not enlarge the text to reach the
  3:1 exemption.

## Focus (SC 2.4.13, 2.4.7)

```css
:focus-visible {
  outline: 2px solid var(--color-focus);
  outline-offset: 2px;
}
:focus:not(:focus-visible) { outline: none; }   /* no ring on mouse click */
```

- Minimum **2px** thick, at **3:1** against what is adjacent to it.
- Never `outline: none` without a replacement. This is the most common single accessibility
  regression in styled UI, and it makes the product unusable by keyboard.
- `outline` follows border radius and never affects layout. A `border` on focus shifts every
  neighbour; a `box-shadow` ring is acceptable but is clipped by `overflow: hidden` ancestors.
- Use `:focus-visible`, not `:focus`, so the ring appears for keyboard users and not on mouse click.
- The focused element must be **scrolled into view and not obscured** by a sticky header or footer.
  `scroll-margin-block: 5rem` on focusable content solves the sticky-header case.

## Target size (SC 2.5.8)

**Minimum 24x24 CSS px** for any pointer target. Use **44x44** as the working baseline - it is the
comfortable-thumb size and it satisfies the stricter AAA criterion.

A visually smaller control can meet this by expanding its hit area:

```css
.icon-btn {
  position: relative;
  width: 1.5rem; height: 1.5rem;   /* visual size */
}
.icon-btn::after {                  /* hit area */
  content: ""; position: absolute; inset: -0.625rem;
}
```

Exceptions: inline links inside a sentence, and targets whose spacing already provides a 24px
diameter of clearance.

---

## Text resize (SC 1.4.4)

Content must remain functional at **200% text size** with no loss of content or functionality.

The direct consequence, restated because it is the most-violated rule in modern CSS: **a font size
expressed purely in viewport or container units fails this.** The viewport does not change when a
user zooms text, so nothing responds. Every fluid size needs a `rem` or `em` term inside `clamp()`.

```css
h1 { font-size: clamp(2rem, 1.5rem + 3vw, 4rem); }   /* correct */
h1 { font-size: 5vw; }                               /* fails */
```

Also test at 400% zoom in a 1280px window, which is the reflow criterion (SC 1.4.10): content must
reflow to a single column with no horizontal scrolling.

## Keyboard

- Everything operable by mouse is operable by keyboard, in a logical order that matches the visual
  order.
- **Use the native element.** `<button>` gives activation on Enter *and* Space, correct role, correct
  focus behavior, and disabled semantics for free. A `<div role="button" tabIndex={0}>` requires all
  of that to be hand-written, and one branch is always missed.
- Never a positive `tabindex`. `0` and `-1` only.
- No keyboard trap. Anything that captures focus releases it on Escape.
- Modals and drawers: move focus in on open, contain it while open, **return it to the trigger** on
  close. The return is the step that gets skipped, and without it the person is dumped at the top of
  the document.
- Provide a skip link to main content as the first focusable element.
- Any hover-revealed content must also be focus-reachable, and must be dismissible without moving
  the pointer (SC 1.4.13).

## Semantics

- One `<h1>` per page. Do not skip heading levels; the level communicates depth, and size is set
  separately by CSS.
- Landmarks: `<header>`, `<nav>`, `<main>`, `<aside>`, `<footer>`. One `<main>`.
- Lists are lists. Tables are tables, with `<th scope>` and a `<caption>`.
- Icon-only controls need an accessible name: visible text, `aria-label`, or visually-hidden text.
  An icon alone announces as nothing.
- Decorative images take `alt=""`. Meaningful images describe their **function**, not their
  appearance.
- Form fields need a real `<label for>`. **A placeholder is not a label** - it vanishes on input, is
  usually below contrast minimums, and defeats autofill.
- Errors: programmatically associated (`aria-describedby`), announced (`role="alert"` or a live
  region), and specific about how to fix the problem. Positioned **below** the field.
- Do not announce state through color alone. Every state also carries text, an icon, or a shape
  change.

---

## Live regions

```html
<div role="status" aria-live="polite">3 results</div>   <!-- waits for a pause -->
<div role="alert">Payment failed</div>                  <!-- interrupts -->
```

`polite` for search results, save confirmations, counts. `assertive`/`alert` only for errors and
time-critical information. An assertive region that fires often makes a screen reader unusable.

The container must exist in the DOM **before** the text is inserted; injecting a populated live
region announces nothing.

Loading states carry `aria-busy="true"` on the region being replaced.

---

## Motion and transparency

```css
@media (prefers-reduced-motion: reduce)       { /* remove travel, keep state change */ }
@media (prefers-reduced-transparency: reduce) { /* opaque fallback for blurred surfaces */ }
```

Mandatory above `MOTION_INTENSITY` 3. See `motion.md`.

Nothing flashes more than three times per second.

## Phase 4 checklist

Run against the built output. Every line is pass or fail.

```
[ ] Tab through the entire page. Focus is always visible and never lost.
[ ] Focus order matches visual order.
[ ] Focus ring: 2px minimum, 3:1 minimum, not obscured by sticky elements.
[ ] Every interactive target is at least 24x24 CSS px.
[ ] Body text 4.5:1. Muted text measured separately. Text on brand fill measured.
[ ] Input borders and unfilled button borders 3:1.
[ ] 200% text zoom: nothing clipped, nothing overlapping, nothing lost.
[ ] 400% zoom at 1280px: single column, no horizontal scroll.
[ ] Every form field has a real label. No placeholder-as-label anywhere.
[ ] Errors are below the field, associated, announced, and say how to fix.
[ ] Every icon-only control has an accessible name.
[ ] One h1. No skipped heading levels.
[ ] Reduced motion honored. Reduced transparency honored if blur is used.
[ ] No state communicated by color alone.
[ ] Modal: focus moves in, is contained, returns to the trigger on close.
[ ] Both color modes checked, if both exist.
[ ] Tested at 320px width.
```

Report the result as pass, or as the specific criteria that fail. "Accessibility: good" is not a
result.
